# Native authentication setup-fault integration

These authored drivers execute only inside the separately owned disposable Arch
ARM7.1.6 guest. They are not Harbour host commands. The setup-feature native ELF
spawns its fixed no-workload supervisor, attempts pidfd_open, discards any acquired
handle and observes the ordinary setup-error branch. No account, credential, PAM module or worker runs.

The hardened passing selection requires the initial occupied Setup report before
queuing `S?`, zero partial residue and a fresh identical report received within
250ms. This closes the earlier scheduling-oracle gap. A matching retained
nonblocking stdin and postwindow FIONREAD0 corroborate command consumption; that
later sample does not establish the response bound by itself.

The held child remains live T and the parent occupied with sticky cleanup fault.
Proof is frozen before independent driver teardown, which actually waits the
parent9 and adopted child9, then requires both dead pidfds/proc absence, EOF,
empty leaf and global ECHILD. This is not native cleanup or slot reuse.

The launcher must supply the exact selection, fixed ELF, original deadline,
private delegated guest service, canonical readonly backing lock, bounded RAM-only
overlay, no network/devices, actual CLI wait and independent exact-container
absence/input closure. Drivers alone prove none of those outer checks. No binary,
credential or raw private runtime artifact is published. Source copies only
normalize extra terminal newlines where recorded in the
[provenance](../../docs/evidence/native-auth-setup-provenance.json).
