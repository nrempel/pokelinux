# Installed native Messages read path

The normal installed native Messages service reconciles committed local receipts
at startup and reopen with its window closed, and before reads. It releases bounded history to an installed
native Qt window through the existing lifecycle actor. The final disposable
ARM64 desktop run passed eleven groups, including an actual systemd unit, a
registered UID-11010 Wayland window, plain SMS text, two original Omarchy themes,
live switching, denial clearing and authenticated graceful stop. Its production
window binary has no observer or fixture entrypoint. This is a local history
vertical path; production modem receive, ACK, sending, carrier delivery,
notifications and trusted Omarchy lock/focus ingress remain unavailable.

components, installed x86 process tests, actual ARM64 kernel tests, the original
Omarchy execution and inherited AOSP decoder comparisons. No physical phone or
proprietary executable participates. The original decoder/receipt/inbox proof

by `ff8d206cc04b14706a0d40cf255ff0e63fd2279d9be8cb95aa485f9afff3772a`,

## Ownership and current read authority

One lifecycle actor owns policy, launched principals and publication. Its
optional Messages provider owns one persistent child containing `ReceiptOwner`
and `Inbox`; the actor never accesses the raw or projection database. Projection
runs at child startup and before reads, independently of app read permission.
The normal installed entrypoint has no ongoing new-arrival source; desktop
reopen reaches pre-read reconciliation or qualified local worker recovery.
There is no production raw-admission, ACK or send endpoint. The frozen `ac57dd6`
desktop/UI milestone used receipts precommitted by its separately built
`isolated-fixture` helper. The subsequent [synthetic incoming composition](native-messages-incoming.md)
connects a separately built actual frozen-V3 Binder peer to this same sole
supervised raw/inbox child and projects each committed arrival with no window.
Its source messages are supervised independently of reads, its durable
one-attempt marker prevents implicit attachment after local or whole-service
restart, and its read publication uses the existing authority unchanged.
That separate test entrypoint is absent from the normal installed service.

`MessagesRead` is a current data-release permission. It cannot be prepared or
admitted as a historical transferable permit. A private, non-cloneable read stamp
binds the packet's actual kernel PID/UID, launched pidfd generation, policy and
lifecycle revisions, storage child incarnation and absolute BOOTTIME deadline.
The worker request also has an exact source/token association with the owning
connection. Immediately before each nonblocking send attempt, including every
retry after actual EAGAIN, the actor rechecks current policy, lifecycle, principal
liveness/generation, backend incarnation/liveness and deadline. No authority
mutex spans SQLite or Binder work. Data already successfully sent cannot be
withdrawn from a recipient; revocation fences future publication. The supplied
window clears its displayed history on a denied refresh.

The service's root-installed profile fixes executable, UID and arguments. App
requests cannot claim a different identity, and IDs are canonical lower-case
32-hex data identifiers, not permission. The desktop socket admits only the
actual designated desktop UID1000 and one fixed `launch_messages` operation for
`org.omarchy.Messages`; it has no grant, data, arbitrary-app or executable
selection authority. Messages launches begin background-denied. The desktop
fixture observes the actual focused compositor PID before its trusted root
controller changes that lifecycle state. A production trusted lock/focus bridge
is still absent, so startup remains locked and background-denied.

## Local storage, recovery and bounds

The child is the sole raw and projection owner. Re-import of the same exact local
receipt ID is idempotent; equal payloads under distinct IDs remain distinct
messages. Sender, address kind and slot are display grouping only. Malformed,
unsupported and status-report receipts do not become text. Original raw evidence
stays in `ReceiptOwner`; the inbox and window hold no ACK or delivery authority.
Existing exclusions and tombstones survive reconciliation; capacity exhaustion
refuses imports rather than dropping occurrence keys.

The diagnostic receipt snapshot API enumerates only the latest32 receipts. The
frozen `f733d3b` service refused larger history before partial import. The current
[complete enumeration](native-messages-enumeration.md) uses fixed-upper owner-bound
pages instead, with eight imports per worker turn and exact-ID reconstruction.
Ready requires all captured records and a current-tail check;33 no longer silently
limits projection or stops that qualified source. The append-only raw journal
still refuses beyond4096, and raw retention remains unimplemented. Original
deadlines can make a large cold backlog unavailable. Inbox bounds remain4096 keys,
2048 text messages and512 conversations; IPC pages contain at most8 conversations
or2 messages and every packet is bounded to4096 bytes. Read deadlines are1–1000ms.
The actor retains the existing32-record policy-grant budget; this is a total
record limit, not a promise to grant all three permissions to every one of16 apps.
The window stores bounded pages and supports chat/message paging.

Data-release cancellation or deadline invalidates publication. A lost reply is
not a remote effect. A stopped, failed or timed-out local worker keeps occupied
capacity until actual `try_wait` reaping. A successful fixed desktop launch may
request one local recovery attempt, bound to the old worker source and a two-second
absolute deadline. It can start a successor only after that exact child is reaped;
stop, authority failure, source change, valid availability or expiry clears the intent.
The actor records that intent at every successful fixed launch and evaluates it
after all connection retirements in that pass. An older persistent desktop
connection can therefore launch before the old app read reaches EOF without
losing recovery. A ready-but-busy worker does not clear the intent when an
existing read stamp has already lost its principal or current authority, even
if another process still holds that app socket open. The intent is consumed
before the single restart attempt. It does not outlive the two-second bound.
Closing during a held read therefore permits ordinary desktop reopen without a
root restart command. The old connection, query and stamp are discarded; the new
registered app begins background-denied and needs fresh current read authorization.
Explicit root recovery obeys the same reap-before-restart rule. Recovery reopens
and validates the same private SQLite journals and re-imports exact existing IDs.
For the synthetic incoming composition, every such local restart opens history
only; app close during a held read explicitly fails that source. Ordinary app
close with no held read preserves receiving. Recovery never recreates raw arrivals or
replays a modem operation. Ordinary clean service restart and valid hot-journal
rollback recover normally; unresolved ownership, invalid permissions, corrupt
schema/data or failed recovery remain unavailable. Policy-storage uncertainty
keeps the separate existing authority fence; it is not copied onto local reads.
The tested foreign descriptor holder never submits a request; its actual socket
retention is a cancellation fixture, not a general process-tree containment proof.

The SQLite/storage objects are synchronous components running inside the child.
Process supervision keeps the tested controls responsive under actual SIGSTOP;
it does not prove that every filesystem or process-launch syscall can be
interrupted or that an uninterruptible kernel task can be reaped. Failure to
confirm cleanup retains ownership or aborts, never reports a free slot. The
systemd unit uses an authenticated `ExecStop`, control-group teardown,96 tasks
and512MiB bounds; the frozen desktop guest exercised its installed start/stop
path. The subsequent incoming qualification exposed the Stop ACK/completion
race under an actual held policy write. `messages-stop` now pins the exact root
socket peer with `SO_PEERPIDFD` and waits for its actual exit within one original
three-second BOOTTIME budget. The [incoming evidence](native-messages-incoming.md)
separates process exit, systemd Main exit status and private policy seal/restart
validation; unsupported kernels fail explicitly without a numeric-PID fallback.

Raw/inbox directories are0700 and their validated files0600. Only the service
owns them. The app has a separate0700 home/runtime and a distinct UID. Wayland
access and shared appearance access are explicit: only the selected compositor
socket, exact regular appearance files and necessary parent traversal/watch
paths get ACLs. The fixture proves that a separate private desktop-home file
remains unreadable; it never recursively grants the home. This fixture ACL
setup is not a production dynamic-session ACL installer. Compositor protocol
containment, encrypted storage, process-tree/kernel-failure behavior and platform
retention/forensic erasure remain separate qualification work. SQLite secure
removal does not prove erasure from backups, swap or storage media.

## Renderer and evidence

The window references the unchanged shared `PhoneThemeFiles`, `PhoneTheme.qml`
and `ThemePalette.js`, with original Omarchy's installed theme values and fonts.
The guest runs pinned public Omarchy v4.0.4 with the recorded Qt namespace patch
and a read-only appearance observer plugin; it does not copy a private palette.
Its controls use those typography, spacing, foreground, surface, border, accent,
focus, pressed and disabled values. All sender/body/status content uses
`Text.PlainText`; no message supplies rich text or a resource URL. Window titles
are constant, and service/UI code does not log raw receipts or message text.
The client owns a Qt worker thread. Every RPC admission, send/receive loop and
completion checks valid BOOTTIME and stop state. Close uses bounded cleanup
slices and requires actual thread-exit observation before deleting the worker.
Clock or exit-observation uncertainty aborts before uncertain member destruction.
The separate [worker evidence](native-messages-ui-worker.md) distinguishes real
Qt/socket execution from caller clock, wait-return and completion-delay injection.
Its GUI callback uses generation fencing, not a new service authority check or
a later queued-delivery deadline. It does not claim real suspend or a kernel
task that cannot be interrupted.

An isolated observer measures only synthetic fixture booleans/counts, appearance
and screenshots; it is absent from the production target.
