# Native Messages session composition

The current production owner can explicitly compose local Messages history with
Sounds. A later [prepared native x86 session](native-messages-prepared-tracer.md)
now executes the current normal Rust-backed Messages window through denial,
granted authored history, live Omarchy themes and revocation with owned Stop.
The source epochs below retain their separate host/staging limits. Cold startup,
ARM GUI and the full [smartphone goal](smartphone-goal.md#completion-matrix) remain
open.

## Selected implementation

The root-installed configuration requires `appearance_socket` and a tagged
`messages` field. `{"mode":"disabled"}` requires only fixed UID11042 Sounds.
`{"mode":"history","runtime":"…","raw":"…","inbox":"…"}` requires Sounds
and fixed UID11010 Messages. Each profile has exactly six absolute arguments:
private HOME, private runtime, canonical Wayland path, appearance socket, session
`app.sock` and protected installed appearance-QML directory. Unknown modes,
implicit defaults, extra roles/fields, wrong UIDs and mismatched paths are refused.
The three history directories must already exist, be root0700 and have distinct
identities from each other and session runtime/policy/display.

History mode retains the existing Projector outside subsequent fallible setup
and supplies it to the same lifecycle actor. The same owner executable dispatches
its Messages writer and independent readonly worker entries. Returning cleanup
fences Source and history before either drain spends one shared original
two-second cutoff; unresolved occupancy aborts. The display Factory admits the
two fixed app roles and retains the existing actual-compositor credential/pidfd
checks and fresh per-app listener/SDK ownership. Configuration and launch grant
no read authority. No incoming/backend selector, retry or Source revival is added.

The Makefile defines eight installed paths: owner, Sounds and Messages launch
clients, both desktop files, unit and two examples. It activates no service.
The Messages desktop client targets the session launch endpoint. Normal Messages
Main/CMake now select the shared `PhoneAppearanceClient`/`PhoneAppearance.qml`,
without selecting the HOME theme-file reader or a fallback. Appearance state
remains separate from Messages authority. See the [owner instructions](../native-session-owner/README.md)
and [UI instructions](../native-messages-ui/README.md) for build/staging commands.
