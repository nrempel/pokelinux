# Native suspend coordination

`native-suspend/` implements an injected-descriptor, one-shot Rust coordinator. It is a tested coordination boundary, with no production suspend service or retained-vendor Binder frontend. It opens no paths, controls no host suspend interface, starts no worker, and leaves the committed `native-power/` arbitration proof unchanged.

An owned authority arms one coordinator instance. A wake object increments the counter once, supports idempotent explicit release across clones, and otherwise releases at the last reference. An acquisition writes the backend abort signal before waiting for the counter gate, then clears that signal after admission. The coordinator holds the same gate across count commit and `mem` write. A separate attempt gate permits only one in-flight attempt; a real advisory `flock` on the supplied writer-guard file excludes another cooperating coordinator. Every participant for one backend must open the same guard file independently. Retained authority, wake and worker references retain that file lock after a public coordinator handle is dropped.

`stop()` and `snapshot()` use atomics and remain responsive while a backend operation is pending. Snapshot fields come from one atomic observation. The caller owns and must join any worker it starts. Stop prevents a subsequent `mem` call after a count operation returns; it cannot reverse an already entered kernel write. Successful `mem` IO means only that the write returned. There is no automatic suspend loop, rearm, or retry. Authority loss, stop and uncertainty are terminal for that instance. Uncertainty takes precedence over a racing stop, and a backend unwind latches degradation and rolls back an unpublished wake reservation.

The FD backend takes four owned descriptors: count, state, abort and unlock. It sets nonblocking flags, reads bounded newline-terminated decimal counts, and uses short cancellable polls with absolute `CLOCK_BOOTTIME` IO deadlines. Read budgets are two seconds and attribute-write budgets one second. Each deadline is created once, retained through `EINTR`/`EAGAIN` and polling, and checked after seek, read, write and poll return. Time asleep consumes the budget; even bytes successfully written after expiry produce uncertainty. An injected clock tests suspend-time jumps without suspending the host. Fragmented fixture counts cannot become prematurely committed numbers. Short writes and generic IO failures are uncertain. In particular, this backend does not equate arbitrary `EINVAL` with a proven kernel changed-count rejection. A backend may return `CountChanged` only when it positively recognizes that rejection; the coordinator then skips `mem` and permits a later explicit attempt. Regular-file and Unix-socket tests qualify these FD operations. `O_NONBLOCK` does not establish that a real sysfs driver cannot block inside `read` or `write`; stopping and joining such an operation remains a kernel qualification gate. A supervisor that can reclaim an owned backend process is required for a truly stuck driver call; this library cannot force a blocked thread to return.

The reference harness compiles the unmodified Android 17 `SystemSuspend.cpp` and `SystemSuspendAidl.cpp` fetched from `android-17.0.0_r1`. Downloaded source stays in ignored artifacts. Our adapters provide POSIX IO, dependency declarations, flags, statistics and service-token fixtures. They redirect the original wake-lock opens to temporary descriptors and reject other `/sys` or `/dev` opens. Original count/state ordering, suspend counter and WakeLock constructor/release/destructor execute in the original source. Metrics, BPF, Android properties, service registration, Binder transport, calling-identity enforcement and feature-enabled `pm_fs_abort` are outside this executable proof. The original implementation creates a detached autosuspend thread and waits only 100 ms in its destructor. Our fixture disables and unblocks it before destruction; a bounded foreground process/container owns the original reference lifetime. The native coordinator creates no detached thread.

The public reference and native behavior compare as follows:

| Boundary | Executed Android 17 reference | Native coordinator |
| --- | --- | --- |
| Count/state IO | Unchanged count commit precedes `mem` | Same gate spans both writes; one explicit attempt |
| Held wake object | Counter blocks commit until release/destruction | Counted object blocks the attempt; caller retries explicitly |
| Concurrent acquire during commit | Writes `userspace-abort` before mutex wait, clears it after admission | Same order with a serialized abort name; temporary FD trace verifies it |
| Changed count | Injected recognized commit rejection skips `mem`, original loop retries | Recognized rejection skips `mem`; no automatic retry |
| State write failure | Actual read-only FD returns failure; source applies backoff and can retry | Actual read-only FD latches degradation; no re-entry |
| Release/deallocation | Original `std::call_once` accounting releases once | Shared native object releases once |
| Controller death | Original token check is backed by real Unix peer EOF in the harness | Native authority destruction disables permanently; Unix fixture drops it on EOF |
| Client death | A reaped Unix peer causes the harness to drop the original WakeLock | A reaped Unix peer causes the fixture to drop one native object |

Both death rows test actual processes and FD closure, with explicit `kill`/`wait` and owned worker joins. The fixture's EOF-to-object mapping is an explicit test adapter. It does not prove kernel Binder remote-object destruction or reference transfer. A Binder object retained by another process need not die when the first client dies.

The retained-client contract recovered from public Android 17 libpower is `int acquire_wake_lock(int lock, const char *id)` / `int release_wake_lock(const char *id)`, using stable AIDL V1 `android.system.suspend.ISystemSuspend/default`. The frozen interface hash is `082a58c2505b703702f34ab8abcb1d1b5e890be4`; that marker matches the selected factory NDK library. `acquireWakeLock(type, name)` returns an `IWakeLock` Binder object; `release()` is one-way. Public libpower always requests PARTIAL, deduplicates held names, and caches its service pointer once. An undeclared service can leave a permanent cached null. A non-null held-name entry can still make acquire report success after service death. Release logs a transport failure but removes its local object and returns success. These source behaviors require explicit retained-client death/restart testing; a reconnecting native Unix protocol would not qualify them. Private static REA evidence supports the selected interface investigation, but no factory vendor code executed and no binary/source equivalence is claimed.

Android 17's service uses UID `system`, groups `system wakelock`, and `CAP_BLOCK_SUSPEND`. Public SELinux policy grants its domain read/write access to the count/state power files and wake-lock files, the block-suspend capability, suspend parameter access, Binder/service registration, and restricted control-service discovery. The source also opens wake-lock files in counter mode, clears `userspace-abort` at construction, and conditionally enables `pm_fs_abort`. UID/group membership alone does not replace these policy and capability requirements. This component has no privileged installer or hardware path profile.

Validation commands are `tools/build-suspend-reference.sh fetch`, `tools/build-suspend-reference.sh build`, and `tools/build-native-suspend.sh build`. The fetch manifest pins 26 public inputs with SHA-256 and size. The build verifies identities before execution and publishes only our synthetic outcome fixture. All eight original-source cases passed on x86. Native validation passed 27 x86 tests, including three actual-kernel process cases, and 24 ARM64 user-QEMU component tests. ARM64 process tests are compiled and individually ignored for user-QEMU. `tools/build-native-suspend.sh arm64-process` emits exact Cargo JSON manifests and a path/hash index for an owned guest-kernel runner; the lifetime test executable uses `--ignored` there. Its helper resolves through `POKELINUX_SUSPEND_LIFETIME_PEER` or the recorded executable directory. Root integration now runs all27 native checks as the unprivileged `alarm` user under the actual Arch ARM kernel7.1.6-1-aarch64-ARCH in system-QEMU, including all three process/Unix lifetime cases and the EINTR unit case. Prior radio/outbox process gates also remain green. This is ARM64 kernel/process evidence; it does not qualify Binder, Pixel suspend controls or hardware. Formatting and clippy with `-D warnings` passed. Runtime red phases were 0 passed / 9 failed for the compiled scaffold; 17 / 1 before fixing duplicate abort-unlock on failure; and 19 / 1 before fixing backend unwind. The deadline test binary also went 0 / 3 before the BOOTTIME correction, and the injected-EINTR real-FD test went 0 / 1. Green followed each implementation change. Late successful count reads, count commits, `mem`, abort and unlock writes all become uncertain, and a suspend-time jump expires a pending real-FD poll. The EINTR case injects the syscall error while retaining a real temporary FD; it does not claim driver signal qualification. [Structured provenance](evidence/native-suspend-provenance.json) records the inputs, commands, synthetic fixture and ignored log hashes.

Remaining gates are concrete:

1. Build the exact frozen V1 Binder frontend, including version/hash transactions, returned-object lifetime, one-way release, registrar/driver selection, calling identity and VINTF/SELinux constraints. Run the original public libpower client against actual kernel Binder, including multiple clients, transferred references, name deduplication, client death, service death and cached-pointer restart behavior. No retained-client ABI completion is claimed here.
2. Qualify the actual kernel count-rejection classification, `userspace-abort`/`pm_fs_abort` behavior during an in-progress suspend, state-write failure semantics, and interruption/reaping of driver-blocked IO. Temporary descriptors cannot establish actual suspend, wake sources or hardware resume.
3. Add a separate device backend profile for paths, ownership, privileges and wake-source discovery, then connect native power policy and service shutdown lifetimes. Pixel paths and node names belong in that profile, not this shared coordinator. Sensor/AOC wake events, thermal policy and native policy leases are not integrated by these tests.

All downloaded public source, selected proprietary inputs and raw REA records remain ignored. The task-owned REA target was closed, its provider reaped, and its private ledger/snapshot retained. No physical phone, host power interface or vendor binary was used; root extended the shared actual ARM64 kernel runner after the component handoff. The owned guest uses a snapshot root disk, read-only project export and no network; no physical phone is involved.
