# Native presentation environment handoff

The separate PID1 shell needs the compositor's instance signature as well as its Wayland display. The recorded cold normal-session launch reached the genuine shell, whose journal reported an unset `HYPRLAND_INSTANCE_SIGNATURE`. Updating a later caller's environment cannot change an already started unit. Pinned upstream Omarchy launches its shell from the compositor startup callback and inherits that environment.

The dedicated Rust `presentation-environment` helper hands off exactly `WAYLAND_DISPLAY=wayland-1` and `HYPRLAND_INSTANCE_SIGNATURE`. It is scoped to this selected UID1000 normal profile, not every display name accepted by the session configuration. These values carry presentation metadata and supply no Source, focus, unlock, capture, permission or application authority.

The [packaging snippets](../native-session-owner/packaging/presentation/) retain separate PID1 shell custody. Install the helper at `/usr/libexec/pokelinux/presentation-environment`, the two drop-ins in their named unit directories, and load `normal-presentation.lua` from the selected normal Hyprland configuration. Genuine Omarchy files remain unchanged. The shell's fixed `ExecStart` uses `launch`; the helper subsequently replaces its own image with Quickshell. PID1 retains the same Main PID and cgroup, with no new supervisor. The cold consumer must require the actual Quickshell image and fixed arguments before accepting startup; seeing the wrapper during its bounded wait is insufficient.

- `clear` runs as root before the next owner launch, permanently drops supplementary groups and UID/GID to1000, then removes only `/run/user/1000/pokelinux-presentation.env` when it is a regular, singly linked UID1000 mode0600 file. Every ancestor is pinned with no-follow directory opens. It neither follows a leaf symlink nor searches for files. Missing state is harmless.
- `publish` runs in the compositor's startup callback as UID/GID1000. It validates the bounded values, exact Wayland/control paths, matching kernel peer credentials and owned pidfds for one live peer. It writes a bounded mode0600 file and atomically publishes without replacing an existing epoch's file. No supplied path, glob, environment dump or file evaluation is accepted.
- `wait` validates under UID1000. One five-second `CLOCK_BOOTTIME` budget starts before filesystem work. It checks exact two-line syntax, file ownership/mode/link count, both socket peers and unchanged file state. Missing state can wait within the original budget; malformed state fails. The containing runtime must be UID/GID1000 mode0700. Socket permission bits are not assumed from synthetic fixtures: type, owner and the actual same live peer are checked inside that private runtime.
- `launch` performs that same bounded validation, overrides only the two presentation values in its inherited static unit environment, checks the original deadline again, and execs `/usr/bin/quickshell -n -p /usr/share/pokelinux/omarchy/shell` in the same PID. It never evaluates the file or imports other compositor variables.

There is no `EnvironmentFile` integration. systemd reads such files before each command, including before a validator in `ExecStartPre`, then reads them again before `ExecStart`. A UID1000-controlled pathname would therefore make PID1 a privileged reader before validation and allow link replacement. Reading and parsing only in the UID1000 wrapper avoids that interface. This ordering was checked in primary documentation; it is not a new executed PID1 timing claim. [systemd.exec](https://freedesktop.org/software/systemd/man/latest/systemd.exec.html), [systemd.service](https://www.freedesktop.org/software/systemd/man/261/systemd.service.html).

UID1000 still controls its own presentation metadata. A peer check is a point-in-time observation, not executable authentication or a guarantee of future compositor liveness. Source retains its existing transport and strict policy. The runtime file must never carry secrets or permission inputs.
