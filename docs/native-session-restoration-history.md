# Retained native Messages behind session restoration

The private restoration tracer now releases actual native Messages pages through
the existing Rust Projector writer and independent readonly child. A persistent
UID11010 app is denied while locked and after arming; only a later exact typed
Source event and the sole policy worker's synced clear release its conversation/
message queries. A second case relocks, cleanly closes the actor, reuses the exact
raw/inbox directories and recovers the same two message receipt IDs after fresh
lock admission and restoration. It seeds each retained dataset once.

Authentication and Source remain private authored test facts. SMS data is the
existing authored two-occurrence `hello` seed. The history provider, policy worker,
Messages writer/reader, SQLite paths, app credentials and returned pages are real.
There is no production completion constructor, broker or new success ingress.
This is a headless installed-worker composition, not normal Qt, original Omarchy
unlock, modem/ACK or physical-phone proof.

keeps the source/build/runtime selections separate.

## Composition and ownership

The lifecycle unit-test crate has a different Rust compilation identity from the
normal lifecycle dependency used by Messages. A dev-only support library in the
existing authority fixture owns the actual Projector and exposes its complete
Provider contract through inherent methods and a neutral token/packet event.
The local cfgtest adapter delegates every method and maps that enum identity.
It preserves the returned packet bytes, token, original read deadline,
cancellation, incarnation, readiness, incoming status, occupation and bounded drain.
No authentication stamp crosses this bridge.

`messages-service` runs only its existing worker dispatch arms. It does not launch
a second policy actor. The lifecycle service retains its sole policy worker and
normally polls/drains the real Messages provider. Trusted root-installed helpers
and private policy/history directories use the existing validation. Seed children
have actual parent waits0 and output EOF before the provider starts. The driver
never independently stops or waits the Messages children to manufacture closure.

The first case queries one conversation and two `hello` occurrences with distinct
canonical receipt IDs. Policy operation receipts are checked separately and do
not become message IDs. The second case obtains those native pages, performs an
actual UID1000 relock, observes a synced pending lock and actual app denial, and
closes normally with a clean seal. A fresh actor/provider over the same data must
start denied. Its fresh actual lock, independent private attempt and later event
permit pages containing exactly the original message IDs. No reseed, new database
or unlocked-Source shortcut supplies the result.

Both epochs in the reopen case compare the sole policy worker against its retained
pidfd through ProcessView. Actual Messages writer and readonly children are bound
to their exact role/socket paths and retained for death/proc-absence observation
after service-owned drain. Numeric app/storage/Messages Child wait statuses are
not independently exposed. Service and heartbeat threads are joined; the test
parent has actual wait0, output EOF and proc absence.

The support facade's early-error Drop attempts normal bounded drain before aborting
on unresolved occupation. Astra source-reviewed this path; successful runtime
cases do not independently qualify an injected early initialization failure.
