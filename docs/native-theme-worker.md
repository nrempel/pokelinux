# Owned native theme font worker

This correction changes only `PhoneThemeFiles` ownership and completion qualification. The prior original Omarchy theme proof remains at `artifacts/native-theme/runtime/green` and its existing provenance report remains unchanged. The new Qt/process results are in `artifacts/native-theme-worker`, with a separate graphical replay at `artifacts/native-theme/runtime/green-worker`.

The reader disconnects process/file callbacks and stops both timers during teardown. After requesting termination of its direct `fc-match` child, it requires successful `waitForFinished(1000)` and `NotRunning` before allowing member destruction. A failed wait observation or occupied process state aborts the local GUI process before the `QProcess` member destructor can perform an implicit wait. This is a failure disposition, not proof that an unobserved kernel child has been cleaned up. Installed supervision and responsibility for a truly uninterruptible orphan remain unresolved.

Original [Qt 6.8.2 QProcess source](https://github.com/qt/qtbase/blob/v6.8.2/src/corelib/io/qprocess.cpp) performs an additional wait in its destructor when its state remains running. The selected original source files are hashed in [the public manifest](../native-theme/worker-tests/public-manifest.json); source copies remain ignored. The running probe links the actual Qt library.

The 1500 ms timer assists cancellation. Admission and completion also sample real `CLOCK_BOOTTIME`; invalid clock samples prevent admission/publication, and completion must be within its recorded budget. File/generation qualification and the last valid concrete family remain unchanged. [Linux clock documentation](https://man7.org/linux/man-pages/man3/clock_gettime.3.html) distinguishes elapsed boot time, including suspend, from `CLOCK_MONOTONIC`. The tests do not suspend a machine: they demonstrate that real late completion is refused even when Qt timer callbacks have not been delivered.

The actual `/usr/bin/fc-match` child blocks on an own private fontconfig include FIFO in an isolated, unprivileged, no-network container. The harness does not substitute the helper executable. Normal termination observes the real child being reaped. For the failure case, a test-only ELF link wrapper calls the real Qt wait, observes successful cleanup, and then reports `false` to the owner. The previous destructor returned; the corrected destructor aborts before the post-destruction marker. This is injected observation uncertainty after real cleanup, not a real failed reap or D-state child.

A second test withholds the application event loop for 1.8 seconds, releases the FIFO, and lets the original Qt synchronous wait deliver actual process IO/completion. The test records real elapsed boot time and zero timer callbacks. The previous reader published the result; the corrected reader rejects it. Additional test-only link wrappers inject boot-clock errors at admission and completion. Private member access is confined to a derived test header; production has no fault selector or injected clock.

Run `python3 tools/prepare-native-theme-worker.py` to create/verify the read-only pre-correction source snapshot from the own reverse patch and hashes. `tools/native-theme-worker-suite.sh red` builds that snapshot; `green` builds the production reader. Both execute the real Qt/process boundary, preserve previous output directories and own their named container. The tests disable core-file generation for the intentional abort. Current exact results and gates are in [the worker provenance](evidence/native-theme-worker-provenance.json).

The separate offscreen regression uses the actual Rust daemon/CLI and staged native app. The graphical replay executes the same pinned original Omarchy scripts, shell and native renderer as the historical proof, with a new output path. Neither scope proves installed native app/service supervision, actual suspend/resume, uninterruptible-task cleanup, vendor cleanup or physical phone behavior. Other process owners, including the existing `PhoneRpc` worker, are outside this correction.
