# Native Linux Binder transport qualification

The target is a Rust radio client running in Arch userspace. Android's matched
kernel and vendor services may still be required; using their Binder interface
does not by itself require Android libc in the client.

## Selected dependency and first boundary

The first transport candidate is [rsbinder](https://github.com/hiking90/rsbinder),
version 0.12.0, pinned with Cargo.lock and default features disabled. Its Rust
implementation provides kernel Binder on Linux. The client does not enable its
socket RPC transport or link AOSP libbinder. Upstream source is Apache-2.0;
transitive dependencies retain their own licenses.

`native-radio` currently contains a kernel IPC qualification binary. It opens
`/dev/binder`, checks the context manager descriptor, pings it, looks up the
existing `activity` service, checks its descriptor and pings that remote object.
It also subscribes to activity-service registration notifications, receives a
one-way callback into its own Rust Binder object, checks the transferred service
handle and pings it. It then unregisters its notification subscription. It sends
no radio commands and registers no service.

The initial run and the final locked offline rebuild both passed with SELinux
enforcing. [Source and binary provenance](evidence/kernel-binder-provenance.json)
records the verified identities and output. The binary was compiled
for `x86_64-unknown-linux-musl`; ELF inspection shows no interpreter segment.
Thus the client used Linux libc and the real Binder driver to reach separate
Android service processes. This is stronger evidence than an in-process Binder
capture or a Rust-only mock. The Android emulator remains the test peer; this
result does not mean all Android services have been replaced.

## Reproduce on temporary Harbour or another Linux KVM host

Prepare the Android framework environment documented elsewhere in this repository,
then run from the repository root:

```sh
bash tools/build-native-radio.sh prepare  # Fetch pinned dependencies and build tools.
bash tools/build-native-radio.sh build    # Locked build with network disabled.
bash tools/framework-suite.sh binder-kernel
```

The suite owns a disposable emulator container on an internal Docker network,
addresses only `emulator-5554`, checks SELinux enforcement and removes its owned
container/network afterward. It does not use host ADB or a physical device.
Results are written under ignored `artifacts/native-radio/`.

## Still required

- Generate or implement the recovered vendor radio interface and callbacks.
- Connect the native lossless request planner through this real transport.
- Verify cross-process callback objects, one-way requests, error propagation,
  Binder death, request correlation and bounded shutdown.
- Verify the Pixel vendor service's interface version, service discovery,
  permissions and accepted transaction semantics.
- Qualify ARM64 kernel IPC. The x86 emulator test is not ARM64 Binder evidence;
  the separate ARM64 codec/planner tests do not cover kernel Binder.
- Recover and verify native IMS policy and state machines, modem operation,
  carrier registration and physical audio.

The existing Android framework bridge remains reference test infrastructure.
This qualification does not alter the goal of native phone services or establish
a complete production radio transport.

## Callback verification

The callback check first failed against the old binary, which only reported the
lookup/ping result. After implementation, the static Linux client received the
Android service-manager callback, verified the name and remote interface, used
the transferred Binder handle, and received successful unregistration status.
The locked offline build and clippy checks passed.

A bounded one-entry channel keeps the callback handler from blocking a Binder
worker. The probe waits up to five seconds for receipt and attempts unregistration
even after a timeout. The success path is executed; timeout cleanup, callbacks
already in flight after unregistration, service death, and production shutdown
have not yet been qualified. This is not a vendor radio callback test.

## Vendor response metadata binding

The recovered `RadioExternalResponseInfo` field schema is now expressed in AIDL
and generated by pinned rsbinder-aidl 0.12.0. Seven original Android typed-object
fixtures verify the presence marker, size prefix and five signed integer fields
in both directions. Boundary values exercise field order and signed encoding;
they are not evidence that negative slot IDs, lengths or error codes are valid.

[Source and fixture provenance](evidence/response-info-provenance.json) records
the tested binding and original-byte identities.

The native decoder rejects the tested invalid size prefixes, truncated objects
and bytes left outside the declared object. Tests do not yet cover a complete
radio response transaction, all malformed inputs, or callback reassembly.
The generated binding is available to native code but is not yet wired into a
production vendor callback receiver. The build script runs its tests on static
Linux x86-64 and ARM64/QEMU.

## Explicit response argument decoder

`decode_response_arguments` now decodes transaction 1 and 2 into `RadioResponse`
events. The caller must first validate the Binder interface token; this function
starts at the argument boundary. Raw and segmented responses have distinct kinds.
The two segmented integers remain opaque parameters until sender-side semantics
are verified. Unlike the original empty segmented handler, decoding does not
silently discard this input.

[Source and fixture provenance](evidence/response-arguments-provenance.json)
records the tested native decoder.

Four argument fixtures were built with Android Parcel and the original metadata
class, then exercised through the original receiver. Native tests run the actual
Rust decoder through rsbinder's Parcel reader. They check preserved metadata and
payload bytes, explicit segmented events, rejection of every truncated prefix,
unknown transaction codes, trailing bytes, null metadata, and null/oversized
payload lengths. All fixture bytes can be reproduced independently from standard
framing and synthetic integers/bytes; they contain no copied vendor payload.

The decoder neither consumes pending requests nor queues callbacks. It preserves
metadata without claiming its modem semantics. It is not yet connected to a
production Binder receiver, and does not implement reassembly or response policy.
