# Native Linux Binder transport qualification

The target is a Rust radio client running in Arch userspace. Android's matched
kernel and vendor services may still be required; using their Binder interface
does not by itself require Android libc in the client.

## Selected dependency and first boundary

The first transport candidate is [rsbinder](https://github.com/hiking90/rsbinder),
version 0.12.0, pinned with Cargo.lock and default features disabled. Its Rust
implementation provides kernel Binder on Linux. The client does not enable its
socket RPC transport or link AOSP libbinder. Upstream source is Apache-2.0;
transitive dependencies retain their own licenses.

`native-radio` contains a kernel IPC qualification binary and a request transport
library now tested against a separate synthetic Java peer (see the final section).
The original qualification binary opens
`/dev/binder`, checks the context manager descriptor, pings it, looks up the
existing `activity` service, checks its descriptor and pings that remote object.
It also subscribes to activity-service registration notifications, receives a
one-way callback into its own Rust Binder object, checks the transferred service
handle and pings it. It then unregisters its notification subscription. It sends
no radio commands and registers no service.

The initial run and the final locked offline rebuild both passed with SELinux
enforcing. [Source and binary provenance](evidence/kernel-binder-provenance.json)
records the verified identities and output. The binary was compiled
for `x86_64-unknown-linux-musl`; ELF inspection shows no interpreter segment.
Thus the client used Linux libc and the real Binder driver to reach separate
Android service processes. This is stronger evidence than an in-process Binder
capture or a Rust-only mock. The Android emulator remains the test peer; this
result does not mean all Android services have been replaced.

## Reproduce on temporary Harbour or another Linux KVM host

Prepare the Android framework environment documented elsewhere in this repository,
then run from the repository root:

```sh
bash tools/build-native-radio.sh prepare  # Fetch pinned dependencies and build tools.
bash tools/build-native-radio.sh build    # Locked build with network disabled.
bash tools/framework-suite.sh binder-kernel
```

The suite owns a disposable emulator container on an internal Docker network,
addresses only `emulator-5554`, checks SELinux enforcement and removes its owned
container/network afterward. It does not use host ADB or a physical device.
Results are written under ignored `artifacts/native-radio/`.

## Still required

- Complete the native indication endpoint and production session owner.
- Qualify the request transport against the actual vendor service; synthetic
  cross-process transport now passes as documented below.
- Verify cross-process callback objects, one-way requests, error propagation,
  Binder death, request correlation and bounded shutdown.
- Verify the Pixel vendor service's interface version, service discovery,
  permissions and accepted transaction semantics.
- Qualify ARM64 kernel IPC. The x86 emulator test is not ARM64 Binder evidence;
  the separate ARM64 codec/planner tests do not cover kernel Binder.
- Recover and verify native IMS policy and state machines, modem operation,
  carrier registration and physical audio.

The existing Android framework bridge remains reference test infrastructure.
This qualification does not alter the goal of native phone services or establish
a complete production radio transport.

## Callback verification

The callback check first failed against the old binary, which only reported the
lookup/ping result. After implementation, the static Linux client received the
Android service-manager callback, verified the name and remote interface, used
the transferred Binder handle, and received successful unregistration status.
The locked offline build and clippy checks passed.

A bounded one-entry channel keeps the callback handler from blocking a Binder
worker. The probe waits up to five seconds for receipt and attempts unregistration
even after a timeout. The success path is executed; timeout cleanup, callbacks
already in flight after unregistration, service death, and production shutdown
have not yet been qualified. This is not a vendor radio callback test.

## Vendor response metadata binding

The recovered `RadioExternalResponseInfo` field schema is now expressed in AIDL
and generated by pinned rsbinder-aidl 0.12.0. Seven original Android typed-object
fixtures verify the presence marker, size prefix and five signed integer fields
in both directions. Boundary values exercise field order and signed encoding;
they are not evidence that negative slot IDs, lengths or error codes are valid.

[Source and fixture provenance](evidence/response-info-provenance.json) records
the tested binding and original-byte identities.

The native decoder rejects the tested invalid size prefixes, truncated objects
and bytes left outside the declared object. Tests do not yet cover a complete
radio response transaction, all malformed inputs, or callback reassembly.
The generated binding is available to native code but is not yet wired into a
production vendor callback receiver. The build script runs its tests on static
Linux x86-64 and ARM64/QEMU.

## Explicit response argument decoder

`decode_response_arguments` now decodes transaction 1 and 2 into `RadioResponse`
events. The caller must first validate the Binder interface token; this function
starts at the argument boundary. Raw and segmented responses have distinct kinds.
The two segmented integers remain opaque parameters until sender-side semantics
are verified. Unlike the original empty segmented handler, decoding does not
silently discard this input.

[Source and fixture provenance](evidence/response-arguments-provenance.json)
records the tested native decoder.

Four argument fixtures were built with Android Parcel and the original metadata
class, then exercised through the original receiver. Native tests run the actual
Rust decoder through rsbinder's Parcel reader. They check preserved metadata and
payload bytes, explicit segmented events, rejection of every truncated prefix,
unknown transaction codes, trailing bytes, null metadata, and null/oversized
payload lengths. All fixture bytes can be reproduced independently from standard
framing and synthetic integers/bytes; they contain no copied vendor payload.

The decoder neither consumes pending requests nor queues callbacks. It preserves
metadata without claiming its modem semantics. It is connected to the native receiver described below, but that receiver has
not been connected to a vendor service. Reassembly and response policy remain
unimplemented.

## Bounded native response receiver

`new_response_receiver` wraps the decoder in a VINTF-stable rsbinder Binder
endpoint. The original Java stub marks that stability in its constructor; its
version and interface hash have now also been checked by original-code execution.
The native endpoint serves those metadata transactions. Initialize ProcessState
before exporting or dispatching this endpoint.

The rsbinder wrapper validates the interface token before our decoder runs.
Known malformed responses, queue overflow and consumer loss latch a terminal
failure. Queue sends never wait for capacity. A short mutex serializes sends and
failure transitions; the inbox refuses buffered events after it observes failure.
The session owner must drop the failed endpoint and fail its outstanding requests;
that owner integration is still outstanding. The endpoint cannot reset itself
and silently continue after losing a response.

Five tests exercise the real rsbinder dispatch wrapper inside the x86 emulator:
wrong-token rejection, malformed-call failure without delivery, full-queue failure,
consumer loss, and matching interface metadata. They require real Binder process
initialization and are explicitly ignored in ordinary Cargo runs. The build
collects the exact static test binary from Cargo's JSON output; `binder-kernel`
pushes it only to the owned emulator and requires all five ignored tests to pass.
[Provenance](evidence/response-receiver-provenance.json) records this scope.

These receiver transactions are local dispatches, not kernel-crossing vendor
calls. The separate service-manager cross-process callback test still passes.
ARM64 argument tests pass, but ARM64 receiver IPC, vendor registration, sender
identity/permissions, service death and production session recovery remain open.

## Original registration and teardown contract

The original command proxy now runs against synthetic Android Binder capture
endpoints in the owned emulator. Five cases verify transaction 5 registration:
response handle, indication handle, client-name string, synchronous exception
header and returned signed client ID. Handle identity and order are checked.
A synthetic SecurityException is propagated; rejected transactions produce
RemoteException without automatic retries. Null fields and a negative returned
ID are preserved by the proxy; this does not establish that a vendor accepts them.

Teardown is transaction **1**, with one client-ID integer and the one-way flag.
There is no reply parcel or completion acknowledgement. Successful submission
therefore cannot establish that callbacks have stopped. The native session must
invalidate its local callback generation and pending requests independently of
remote cleanup. A synchronous registration error must not trigger blind retries:
a transport failure can leave the remote registration outcome unknown.

[Registration evidence](evidence/registration-provenance.json) records source,
APK, built oracle and output identities. All previous original-bytecode tests
also passed in this run. These are local original-proxy captures, not native
registration or cross-process vendor qualification. The next integration gate is
a separate synthetic service process exercising the production native adapter,
with explicit test-only discovery permissions, callback delivery and death.

## Indication recovery notes (static only)

REA inspection of the same APK finds a distinct indication protocol: raw
transaction 1 contains two integers and a byte array; segmented transaction 2
adds two integers. The concrete indication adapter treats these as message ID,
slot ID, payload, segment index and total length. It filters by its configured
slot and maintains a segment map keyed by message ID. The segment accumulator
counts only the first occurrence of an index; the adapter delivers when the
accumulated length equals the declared total and then removes the message entry.

This is static decompiler evidence, not an execution result or a modem contract.
It does not establish bounds, ordering guarantees, concurrency rules for repeated
message IDs, timeout behavior, or callback sender flags. Native indication work
must test those cases explicitly and bound memory and incomplete-message lifetime.
Do not reuse the empty original segmented-response behavior for indications.

The inspected methods are `IOemSlsiRadioExternalInd.Stub.onTransact`,
`OemSlsiRadioExternalIndAidl.OemSlsiRadioExternalIndStub.rilExternalRawIndicationSeg`,
and `OemSlsiRadioExternalIndBase.SegmentRilMessage.addDataSegment`. Raw decompiler
outputs remain excluded from the public repository.

### Original accumulator execution

The owned emulator now executes the original `SegmentRilMessage` constructor,
`addDataSegment` and `getMessageData` methods with synthetic fragments. Its unused
outer instance is null; this does not exercise adapter startup or modem access.
All eight cases pass, alongside the existing original-code suite:

| Case | Observed original behavior |
|---|---|
| Ordered and reversed arrival | Concatenates bytes in index order |
| Identical duplicate | Does not count its bytes twice |
| Conflicting duplicate | Keeps the first bytes, including when duplicate length differs |
| Index gap or negative index | Byte accounting can reach zero, but assembly throws NullPointerException |
| Excess bytes | Returns negative remaining length; direct assembly still returns all supplied bytes |
| Zero total and empty fragment | Returns zero and assembles an empty list |

[Source and artifact identities](evidence/indication-assembly-provenance.json)
make this reproducible. The excess-byte case calls assembly directly; it does
not claim the enclosing adapter would emit that result. The test does not prove
conflicting-total handling, multiple interleaved messages, cleanup, timeouts or
the producer's guarantees. Original crashes and unbounded retention are not
requirements for the Rust implementation.

No recovered fragment field identifies a particular occurrence of a message ID.
An old fragment and a new fragment with the same slot, message ID and total can
look like one valid message. Local session epochs can reject old callback objects;
they cannot prove the vendor has discarded old fragments. Timeout and reconnect
must not be documented as a verified vendor flush boundary without evidence.

### Original adapter execution

Seven additional cases execute the original AIDL owner constructors and callback
`onTransact`, with an injected listener and synthetic parcels. Wrong-slot input
is ignored. Different message IDs keep separate accumulators; successful delivery
removes the entry and permits reuse. A synthetic old head and new tail with the
same ID/slot/total produce mixed output without detection.

The first fragment's total controls completion, but the final fragment's total
controls the result constructor's copy length. Changing the total therefore
produces padding or truncation in the tested cases. A listener exception retains
the completed entry; a later conflicting duplicate retries the first bytes.
Missing-index failure also retains state, and a later gap fill can overshoot the
total without delivery. These are consumer observations, not proof that a real
producer emits these malformed sequences.

### Native single-candidate assembly

`native-radio::assembly::Assembly` reconstructs one candidate with explicit local
byte and fragment/index limits. It preserves valid numeric ordering and exact
duplicate behavior, rejects conflicting totals/payloads and invalid coverage,
and permanently invalidates a candidate after any error. Completed instances
cannot accept another message. Empty index-zero/zero-total assembly is explicit;
empty fragments in nonempty messages are rejected as a local supported-input rule.

This is not yet a production session owner. It has no independent timer, epoch
fence, aggregate multi-message budget or vendor resynchronization guarantee.
The owner must supply those before delivering results to phone consumers. Peak
payload allocation can reach twice the configured candidate byte limit during
assembly, plus bounded map overhead; the caller owns the input event allocation.

## Native request transport across processes

`RadioTransport` now submits recovered registration, raw/segmented request and
teardown transactions through rsbinder. It uses `native-ims::RequestParts`, so
4096-byte payloads retain the final full segment. It preserves registration
exceptions, never retries sends, and reports how many earlier parts were submitted
when a request fails. Submission is not modem acceptance. Discovery, session
ownership, deadlines and recovery are still required.

The independent Java peer runs as an untrusted app. A test-only instrumentation
watcher transfers its Binder handle to the static musl client running as shell.
The installed framework's original proxies verify the exact bootstrap layout
before the test starts. Framework transaction 51 and the observed status trailer
are confined to this pinned SDK37 harness. The library contains no framework
bootstrap ABI.

With SELinux enforcing, the test passes registration with distinct callback
handles, a nested metadata query, response submission before the registration
reply, and byte-exact payload round trips at 0, 2048, 2049 and 4096 bytes. The peer
checks request fields and one-way flags (separately accounting for the transport's
TF_ACCEPT_FDS flag). A separate test-only query confirms the peer processed clear;
that query is not part of the vendor protocol.

[Provenance and limits](evidence/radio-ipc-provenance.json) identify the executable,
APK, framework, sources and test domains. Reproduce after the standard preparation:

```sh
bash tools/build-native-radio.sh build
bash tools/framework-suite.sh radio-ipc
```

The subsequent native indication endpoint replaces the descriptor-only test
handle. Both endpoints share a bounded event queue and terminal failure state.
Raw and segmented indications pass across processes; fragments preserve
message, slot, segment index and total length. Single-candidate assembly now exists;
production session ownership and safe reuse remain incomplete.

The peer submits indications before returning registration. After the request
round trips, a separate test-only burst overfills the four-event inbox while the
client does not consume it. Both endpoints report QueueFull and the inbox refuses
buffered events. This proves local inbox failure across actual Binder, not driver
buffer exhaustion or session-owner recovery. Malformed argument tests reject
truncation, null arrays and trailing fields on Linux and ARM64/QEMU.

`CallbackInbox::recv_until` now waits directly on the bounded channel. Terminal
failure drops its shared sender and wakes the wait; failure state is checked both
before and after receiving so already-buffered events cannot hide an observed
failure. Three Linux and ARM64/QEMU tests cover timeout without invalidation,
terminal wakeup, publisher loss and buffered-event rejection. The wait deadline
bounds blocking only; it does not establish event freshness, suspend-aware expiry
or atomic publication against later invalidation. Those remain session-owner work.

Each callback pair now exposes a cloneable `CallbackControl`. Explicit `cancel()`
invalidates both endpoints and closes the shared sender, waking a local waiter.
It preserves the first terminal failure and cannot reset the stream. Dropping one
control clone does not cancel the others. This cancels local callback consumption;
it does not cancel an in-flight remote Binder transaction, clear a vendor
registration, or settle pending phone operations. Those require the session owner.

The updated real-Binder test observes clear, registers fresh endpoints with the
same synthetic client ID, drains initial events, then asks the independent peer
to submit a delayed malformed indication. The required byte array is absent.
The blocking native inbox returns `MalformedCallback`; its response endpoint
also fails, while the old pair retains `QueueFull`. A separate local waiter exits
with `Cancelled` after explicit control cancellation. [Provenance](evidence/callback-cancel-provenance.json).
The peer trigger is test-only, and a one-way submit is not remote acknowledgement.
This proves local state separation and remote parser failure delivery, not service
death recovery, stale-fragment isolation or a vendor flush guarantee.

`RadioTransport::watch_death` now returns a guard that owns the strong death
recipient required by rsbinder 0.12. Arm it before registration and retain it for
the session lifetime. Service death invalidates the shared stream as `ServiceDied`;
a failed link invalidates it as `ServiceDied` for `DeadObject`, otherwise
`MonitoringFailed`. Dropping the guard cancels local consumption before a
best-effort unlink. It does not clear vendor registration or resolve the outcome
of already-submitted requests. First failure remains authoritative.

The owned emulator verifies guard drop/cancellation, re-arming a new watch,
successful registration followed by actual peer-process exit, and rejection of
a watch on the already-dead Binder proxy. The active stream returns `ServiceDied`
without a concurrent outgoing call. The dead-proxy link returns `DeadObject` and
also invalidates its fresh stream. [Execution identities](evidence/radio-death-provenance.json).
Death during registration now also passes: the synchronous call returns
`DeadObject` and the pre-armed callback stream reports `ServiceDied`. The normal
suite passes afterward in fresh processes. [Evidence](evidence/registration-death-provenance.json).
Other monitoring-link errors, in-process restart/reconnect and owner-level
late-event fencing remain separate tests. These results do not establish modem reset.

The late-callback test keeps the failed old response endpoint alive in the peer
after clear and replacement. It reuses client ID 42 and response serial 777,
sends payload 99 to the old endpoint and payload 7 to the new endpoint, using
synchronous transactions for an observable comparison. Binder pings succeed on
the old endpoint before and after rejection. Android surfaces its failed
transaction as `DeadObjectException`; that exception alone does not prove process
death. The old stream retains `QueueFull`, and the new stream receives only
payload 7. [Evidence](evidence/late-callback-provenance.json).

These are raw synthetic synchronous transactions; the peer does not call
`readException()` on the successful empty callback reply. Vendor callback flag
compatibility remains unqualified. Endpoint isolation does not fence results
already consumed by an owner or partial fragments delivered to a fresh endpoint
from retained vendor state. Those require separate owner and producer evidence.

The old provenance above records the earlier request/response milestone. The
[indication report](evidence/radio-indication-provenance.json) records this extension.
Neither establishes actual vendor service behavior or production recovery.
[Remaining integration gates](native-radio-integration.md).

## Native owner publication boundary

A new `session-owner` scenario runs the native `RadioOwner` against the independent
Java Binder peer. Events consumed before cancellation or replacement cannot update
the owner's current raw-response snapshot. Registration IDs are deliberately reused,
and late callbacks to a failed old endpoint cannot invalidate the replacement.
Linux and ARM64/QEMU tests cover additional ownership and failure cases. See
[the execution record](evidence/radio-owner-provenance.json) and
[remaining owner work](native-radio-owner.md). This is not native call/IMS state,
worker recovery, or physical hardware qualification.
