## Correction and executed red

selected installed-app fixture handled only storage and writer selectors. Before
the dispatch correction, the new core and that exact old fixture were frozen in
`combined-read-selector-red-build`. The first actual ARM attempt reached a ready
lifecycle actor but could not obtain a ready reader. It remains an unselected
incomplete setup observation, without Qt/application qualification.

A second executed red, `combined-read-selector-observed-red-arm`, observed that
same selected ELF reject the exact reader selector with `PermissionDenied` and

No app had launched and the read child had not become observable as a ready
reader; that result does not claim a completed Qt setup or a tracked successful
reader lifetime. The rejection probe, writer and other tracked children were
reaped. The fixture's three-line readonly dispatch was added afterward.

`combined-read-selector-green-build` copies the exact red core snapshot and
its Rust fixture changes only the installed readonly dispatch. Guest ownership
and rejection observations were added before the observed red and used unchanged
in both greens. All66 core source hashes match.
The observer, actor, receiving/read implementation, source lease and production
Qt binaries were not modified. A new mutable scratch target was shared between
these two builds; source and bin selections remain separately frozen. Old
immutable targets were never rebuilt. Cargo inputs were mounted readonly;
builds used8 CPU/12 GiB and no network.

The guest now identifies the actual `--messages-read-worker` when holding a read
and tracks `--messages-worker` independently as the writer. It records each
