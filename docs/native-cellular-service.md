## Provisioning and one attempt

Main takes absolute `--runtime`, `--journal`, `--worker`, `--config` paths and
one absolute `--until-ns`. Runtime and the journal's immediate parent must be
same-effective-UID0700 directories. The protected configuration carries the
selected Binder device, configured service name, expected callback UID and all10
setup arguments, including all21 profile fields. It is operator provisioning,
not a mapping from a vendor raw slot to a SIM/subscription or proof of provider
permission. Production neither imports the authored fixture interface nor calls
its `endpoint()` method.

Configuration loads use a retained directory FD and a regular single-link
same-effective-UID0600 leaf, bounded to32768 bytes. The immediate parent and leaf
are opened with final-component `NOFOLLOW`; FD metadata before/after the complete
read must agree. This does not enforce containment of every ancestor or prohibit
ancestor symlinks. Configuration currently parses through `serde_json::Value`:
unknown and missing fields are refused by its shape helpers, but duplicate keys
are not separately refused and use the JSON parser's retained value. Do not
claim a strict duplicate-key configuration format.

Main computes SHA256 over the exact protected bytes it parses. It passes that
identity as `--config-sha256`; the worker reopens and validates the protected
file, parses it and compares the complete byte hash before Binder initialization.
A valid replacement with the same serial but changed APN bytes is refused by
the host component control. The hash fences content, not inode continuity,
provider identity, delegated authority or future filesystem changes.

`Supervisor` creates and syncs one0600 admission marker and syncs its parent
directory before spawn. Its read-only receipt identifies those actual returned
sync calls and the marker's metadata; it does not prove storage power-loss
survival. The marker remains after failed spawn, Stop, wait and owner recreation.
Existing uncertain admission refuses another child with exit78. No reset,
automatic setup/attachment retry, journal deletion or safe successor operation
is implemented. A fresh runtime directory may be needed for a restart check
because an existing socket path is deliberately refused.

The worker is selected by `--pokelinux-process-worker`. It performs the shared
same-credential parent bootstrap on the final-credential main thread before
config/Binder/thread setup, retaining the exact socket-origin/transferred parent
pidfds and original READY/GO cutoff. The spawning thread keeps its non-Send/
non-Sync supervisor through actual child wait. Trusted executable/procfs/service
manager provisioning remain requirements.

## Submission and historical observations

The worker discovers exactly the configured standard Data service using real
`IServiceManager.checkService`, requires a remote `IRadioData`, version3 and the
frozen Data hash, then retains one endpoint, fresh callbacks and one
`KernelObserver`. Expected callback UID is an explicit config premise. Discovery
and a synthetic fixture barrier do not establish actual modem attachment,
subscription mapping or permission.

An initial frame records the successful observer initial sync and last observed
`NotSubmitted` before callback attachment. The cooperative GO/Ready receipt is
process publication admission, not callback attachment. The initial frame is a
best-effort pipe observation: its absence cannot establish failure, and its
presence is not proof of remote registration or APN readiness.

The owner marks `OutcomeUnknown` before possible setup dispatch. The publication
repair requires the complete Pending frame to be written successfully before
`setupDataCall`; `WouldBlock`/interruption is fatal before that call. This is
whole pipe delivery, not proof that Main has read/admitted it. The parent must
separately bind an actual admitted frame to claim Pending projection. A write,
ordinary oneway return, fixture barrier or response-submission return is not a
matching native callback receipt. The current source does not retry setup.

Status `NotSubmitted` is the last source observation, not a current guarantee
that no request reached the provider. Durable admission already records an
uncertain attempt; a missing Pending receipt or worker death cannot clear that
uncertainty. After a possible dispatch, local cancellation/Stop/death cannot be
relabelled as proven not sent or remote cleanup.

Ordinary `DataOwner.poll()` consumes callback events and obtains fresh kernel
snapshots. Only its first expected-UID, ordinary SOLICITED matching-serial result
settles historical disposition. Both radio error and result cause must be NONE
for `ProviderAccepted{cid}`; other accepted-shaped ordinary results record
`ProviderRejected{radio_error,cause}`. The complete report is immutable after
settlement. `OutcomeUnknown` is not an accepted receipt. ACK_EXP and other
unsupported callback families cannot affirm anything; no acknowledgement or
wake duty is qualified here.

Worker frames require schema1, exact current source incarnation/attempt1,
strictly increasing revision, exact serial/original until, nonfuture and
nonregressing source sample, initial-sync completion and matching retained
namespace for any association. Typed JSON deserialization rejects duplicate,
unknown, malformed and omitted required-nullable fields before projection.
The parent refuses later changes to settled report/disposition. Local retirement
withdraws the association while preserving that historical report and its
source revision/time.

## Report and association bounds

The report preserves every one of the public result's18 fields, including all4
LinkAddress fields, all5 SliceInfo fields, Qos Noinit, empty qosSessions and the
TrafficDescriptor/OsAppId wrappers. This first subset refuses EPS/NR QoS and
nonempty sessions; it does not invent replacement values. Address/DNS/gateway/
P-CSCF vectors are limited to4; relevant text is bounded to128 bytes, ifname15,
TrafficDescriptor count1 and OsAppId256 bytes, with no NUL. The generated
i64 suggestedRetryTime and i8 handoverFailureMode/SliceInfo byte widths are
preserved. DNS/gateway/P-CSCF remain provider reports, not kernel facts.

One frame is a complete JSON object plus LF, at most4096 actual encoded bytes,
including escapes and newline. The encoder refuses excess rather than truncating.
The host control exercises exactly4096 and refuses4097 escaped bytes. Worker and
status shapes use explicit nulls for nullable fields; omission is not null after
the publication repair. This is a finite typed subset, not support for arbitrary
public Data parcelables or a lossless callback log.

A positive association records retained namespace dev/inode, ifindex, witnessed
lifetime, kernel revision and observation CLOCK_BOOTTIME. The existing owner
requires its structural name/local-address/prefix/UP/MTU/scope/flags and infinite
provider-lifetime subset. A matching independently created TUN does not prove
that the Data provider owns or created the link. Kernel and provider observations
are not atomic. No fixture readiness setter or authored APN-context install is
part of production.

Main withdraws a cached association once its kernel observation is at least1s
old on a current-state check. That is a local freshness policy, not a claim that
a link vanished or a suspend/wake delivery guarantee. A later admitted fresh
worker observation may restore a locally aged-out association while the owner
is still eligible; local age withdrawal is not the owner's permanent retirement.
Worker deadline/known fault, EOF/malformed frame, Stop and actual child exit also
revoke current publication, retaining settled history. The service's original
absolute BOOTTIME lease is never renewed.

## Restricted operator interface and custody

The nonblocking CLOEXEC/PASSCRED Unix SEQPACKET socket is same-service UID/GID
only, with exact connected PID/UID/GID checked on every packet. Truncation,
passed rights and credential changes are refused. This is an operator diagnostic
interface, not app permission ingress. Main accepts at most2 clients per turn,
retains at most8, processes at most8 worker read/decode steps per turn and bounds
its input buffer at8192 bytes. Each server client slot has one500ms budget;
status is freshly serialized after current expiry/reap checks on every send
retry. There is no stale response outbox.

Status contains schema/server_pid/worker_pid, local phase, original until, local
sample time, optional fault and one source-tagged observation. Phase values are
`Initializing`, `Observing`, `Unavailable`, `Stopping`. `Observing` means current
worker observation traffic; it need not contain an association or provider
acceptance and never means cellular/internet readiness. Source revision/time
belong to the last accepted worker frame; local phase/freshness changes do not
invent a newer source revision. Fault retention does not rewrite settled history.

The client accepts an explicit absolute `--until-ns`, at most60s in its future;
the selected tracer may choose a smaller fixed cap. It performs a nonblocking
connect, request/receive and, for Stop, exact server socket-origin pidfd exit
observation under that one cutoff. This client is not a reaper and exit
observation alone cannot establish Main's exit code or native worker wait.
Its stdout must be a pipe, set nonblocking, and one complete output line must
succeed. Frames/status/control replies and successful stdout writes are bounded
to4096 bytes. Best-effort lifecycle logs may be dropped and cannot replace
missing qualification evidence.

Parent retirement revokes frame admission before signalling the worker and
starts one2s disposal cutoff. Repeated failures cannot renew it. The parent
retains the child and actually calls its wait path; an occupied child at cutoff
aborts instead of detaching. A deployed service manager must own fallback.
Worker fatal paths use direct process exit rather than potentially blocking
Binder/watch destructors. Native process reaping is local reclamation, not a
Binder pool/thread join, modem deactivation, vendor cleanup acknowledgement or
permission to retry. A Stop ACK only confirms local Stop admission; full success
needs native wait plus the external owner's actual Main wait/EOF and exit code.
