# Native Settings connectivity controls

The normal Settings frontend adds explicit Enable and Disable controls for the
Rust connectivity engine. It displays fresh configured state separately from
pending or unconfirmed action outcomes. Local connection state establishes no
Wi-Fi association or Internet access. The controls use the existing shared
PhoneAppearance bindings for font, spacing and color; this cohort does not
qualify a newly delivered theme provider.

Rust still owns protocol, authority hints, freshness, one-shot mutation admission,
worker state and actual thread join. The Qt adapter translates properties and
captures the Rust BOOTTIME deadline exactly once in the originating click handler.
It sends the explicit desired boolean and that same absolute cutoff through the
existing Settings archive. Programmatic refresh sends no command. OK is local
admission; confirmed state comes from Rust View and preserves uncertainty.

Window close, SIGTERM and QML setup failure after client creation route through
one close owner. It disables refresh and controls, calls Stop once, then uses Qt
timers to poll Join. Free follows actual join; unresolved custody aborts. The
closed signal exits the event loop through a queued connection. No Join or Free
runs inside beginClose, and closing sends no implicit Disconnect. Older
brightness, appearance and network-status owners retain their recorded shutdown
implementations.
