# Static installed wireless selection

The protected installation JSON identifies one exact interface name instead of
persisting namespace inode or interface-index values across boots. Main resolves
that name once from a complete read-only kernel snapshot under its original
three-second BOOTTIME cutoff. Missing or ambiguous names fail startup; there is
no replacement wait, fallback interface or automatic retry.

The observer retains the namespace until Service has opened and checked its own
matching namespace handle. The resolved numeric profile remains internal to the
Main/worker boundary. Worker attachment independently checks the selected radio
and disconnected/unconfigured baseline. Name lookup does not prove continuous
interface ownership: this tracer requires exclusive administration and a
preprovisioned station name.

Two protected-file assertions first fail on the old implementation: static-name
input must load, and the obsolete numeric installation schema must be refused.
The first owner misclassified the build wrapper's normalized exit; its original
failed receipt is retained and the actual assertion failures were reviewed
separately. The candidate passes 52 library tests plus eight owner tests, with
one ignored test, formatting and strict Clippy. Normal host/ARM providers and
an ARM library-test executable compile; ARM library tests are not executed.

A separate generic ARM/hwsim baseline executes the current four-path Main with
static-name input. It returns the exact unknown-interface schema error before
listener, worker journal or actor admission. Independent readback remains
disconnected/unconfigured and the packet peer receives nothing. The desired
functional assertion fails after qualified guest cleanup; QEMU exits normally
and the exact container is removed with inputs unchanged. An earlier host-owner
attempt failed reading a root-owned receipt before creating a container; that
setup failure is preserved separately and is not behavioral evidence.

The candidate now passes the same byte-identical ARM consumer: exact-name
resolution, explicit Connect, two independent capability-free packet round trips,
client close/reopen on the same worker, explicit Disconnect, independent absent
address/association and an 800ms quiet window. Main, actor driver and packet peer
exit normally; the worker is reaped after signal 9 and Main records only external
Stop as its first retirement. Guest waits/EOF, namespace closure, ECHILD, normal
QEMU exit, exact container absence and unchanged inputs all qualify. This uses
authored actor authority with a simulated open AP and fixed local IPv4; it does
not execute normal Settings or Permissions windows.

Installed PID1 composition,
normal Permissions/Settings consent, two-boot persistence, WPA, DHCP/DNS,
Internet and every matched Pixel hardware gate remain open. No physical phone
has been accessed.
